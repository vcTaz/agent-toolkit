# Stage 4 implementation plan

Goal: safely coordinate concurrent assignments without evaluating truth.
Authority: the user's Stage-4 attachment approves implementation; Stage 5 is excluded.

1. Extend immutable Task/Assignment/Message/Run records with explicit work requirements, pinned dependencies, delivery metadata and run limits. Test serialization and frozen provenance; preserve schema-version-1 compatibility through additive defaults.
2. Implement messaging.py for validated targeted routing and delivery snapshots, context.py for immutable bounded selections, and admission.py/policies.py for pure decisions. Test privacy, bounds, dependency ordering, permissions and stale references before wiring execution.
3. Implement a WorkController in orchestration.py. All repository commits and accounting callbacks execute synchronously on its event-loop thread; provider calls run concurrently. Commit dispatch and outcomes as atomic record/event batches. Task requests persist as proposals, never tasks.
4. Exercise failure/retry, cancellation/deadlines, durable shared budgets, reservations, late-result rejection, and varied completion order with real SQLite and fake providers.
5. Independently review, fix regression cases, run the entire source and wheel suites, update architecture/checkpoint documentation, and stop before Stage 5.

Conservative decisions: NEEDS_INPUT follows the bounded retry policy; task requests require explicit later host adoption; only EXPLORER/SPECIALIST/COLLABORATOR roles execute in Stage 4. Run workflow state remains unchanged; a durable work_stop_reason prevents future dispatch on cancellation/deadline/storage interruption when storage is available.
